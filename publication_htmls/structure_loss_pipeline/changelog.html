Structure Loss Pipeline · history

What changed

Every other page on this site describes the dataset as it is now. This one is for anyone who read an earlier version, or an earlier number: the decisions that changed what the dataset contains or what its figures mean, newest first, one line each.

The short version

If you are holding numbers from before 12 September 2026, replace them. A defect in how satellite pixels were read moved most damage features; the frame that decides which buildings a fire contains changed; radar left the model; and the dataset went from five fires of the historical record to all 361 of it. Nothing published before that date carries over unchanged.

the record

Decisions a data user would notice

Newest first. The full technical entry for each is in the project change log, under the date given.
DateWhat changedWhy it matters to you
2026-09-12 The advisory loss call is scoped to the near-perimeter zone The second, advisory destroyed call now takes each fire's threshold from the perimeter-plus-100 m population instead of the whole inventory. Its per-fire thresholds moved from a 0.158–0.792 range to 0.601–0.792 and it calls 15,951 structures destroyed rather than 17,362. The primary call did not move at all.
2026-09-12 The dataset carries the whole historical record 361 fires and 1,770,939 rows of the 2002–2022 survey, verbatim, where earlier versions carried only the five fires that happened to be cached. If you joined on a building identifier, note that four fires' identifiers changed: they are now enumerated per fire over the national release.
2026-09-12 Radar left the damage model The model is optical only. Radar had been promoted under a rule written in advance; on corrected feature tables it no longer cleared that rule, so it was removed. Removing it costs nothing measurable and lets the model run on fires from before the radar archive opened.
2026-09-12 Two flag columns on the historical half The survey's own release repeats 20,296 rows exactly, and 18.3 % of its rows sit at a location a second fire also claims. Both are now flagged per row rather than silently cleaned. De-duplicate on geometry before any pooled count.
2026-09-12 A second loss call ships beside the first Every scored row now carries two calls: one at a fixed threshold and one at a per-fire threshold. Use the fixed one to classify buildings and the advisory one if you are counting them — and say which you used.
2026-09-11 The licence is settled MIT for the code, CC BY 4.0 for the data. Rows whose geometry came from an ODbL-licensed footprint layer are dropped from the released package — 16,247 rows, unevenly distributed, heaviest on rural fires. No DOI has been minted yet.
2026-09-11 An attribution rule for overlapping fires When two fires reach the same building inside each other's observation windows, one rule decides which fire may claim it. Structures called destroyed under two fires went from 271 to 0. Rows ceded to a later fire carry no damage call and say why.
2026-09-10 The frame became the fire's public perimeter Which buildings a fire contains is now decided by its published perimeter plus a ring, matching the historical survey's own rule. It replaced a buffer drawn around inspection points, which enumerated a different population and could not define a fire at all in a state with no inspection programme. It added roughly a third again as many structures and moved no accuracy figure.
2026-09-10 A satellite sampling defect was found and fixed The one that invalidates old numbers. The read window that pulls reflectance for a building could disagree with the coordinates indexing it by one pixel, and the cloud mask was read at a different padding from the bands it masked — so a building's cloud verdict could come from a different pixel than its reflectance. At least one feature changed for 85 % of buildings in the 10 m tables and 51 % in the 30 m ones. Every table was rebuilt and every model refitted.
2026-09-10 The building detector was frozen Detector work stopped at one checkpoint so that later comparisons are about the damage model rather than about a moving inventory.

Source: logs/CHANGELOG.md in the project repository, the dated entry for each row, and docs/release-notes.md. Each entry carries the measurement behind the decision and the commit that applied it; the experiment ledger (docs/experiment-ledger.md) carries one row per idea, experiment and data source, including the ones that failed.
