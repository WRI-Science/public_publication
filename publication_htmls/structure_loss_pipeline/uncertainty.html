Structure Loss Pipeline · uncertainty

How wide are these numbers?

The unit of evidence in this project is the fire, and there are not many fires. Every headline the pipeline publishes carries a 95 % interval from a fire-level cluster bootstrap — resample the fires with replacement, 2,000 replicates — and on the out-of-sample tables that bootstrap runs over eight incidents, two of which hold 84 % of the structures. The intervals are wide. That width is the evidence, not the estimator, and nothing on this page narrows it.

What produced these intervals

All of it is scripts/13_uncertainty_report.py: CPU only, about two and a half minutes for every source, nothing refitted. It reads the out-of-fold predictions already on disk and resamples them. Every summary.json it writes carries a tables_vintage field, so no interval on this page can be read without knowing which generation of the feature tables produced it — all of them here are the v4 corrected-sampler tables. The pre-fix v3 directories were not overwritten and sit beside them on disk.

⚠️ Look at the pooled F1 interval: [0.859, 0.928] against an estimate of 0.9236. It barely reaches above the estimate. That is not a bug — Eaton and Palisades are 84 % of the rows and both score high, so a resample that draws either of them less often falls, and one that draws them more often has nowhere to go. The interval is skewed because the evidence is.

And four seeds move the number by a thousandth while one fire moves it by five hundredths. The seed-to-seed spread that a promotion rule is usually checked against is about fifteen times narrower than the fire-to-fire spread of the same quantity — and it is the fire-to-fire one a ninth incident lives in.

The better-ranked bundle is the worse-calibrated one, which is the clearest sign that the score is an ordering rather than a frequency. The calibrated column ships as destroyed_prob_calibrated beside destroyed_prob, not instead of it, and the operating cut stays on the raw score: isotonic regression is monotone, so it cannot re-rank anything, and moving the cut onto the calibrated axis would change the product without changing the evidence. It costs 0.0017 pooled F1 at the matched operating point.

Calibration is not a per-fire cut rule, and it does not recover the out-of-state threshold loss. Because the map is fitted leave-one-fire-out on 65 of 66 fires it is nearly the same map every time: the raw score at which the calibrated column reaches 0.5 spans only 0.904–0.932 across the Carlson fires, against per-fire best cuts that run 0.64–0.93. A rule that does move with the fire is on the outside-California page.

⚠️ The threshold-free half of the radar claim does not survive the sampler fix. On the pre-fix tables the published reading was that the pooled-F1 gain was the fragile half and "the threshold-free half survives cleanly, which is the half the README leads with". On corrected features it is exactly backwards: mean-fire AUC falls from +0.0017 [+0.00005, +0.0037] to +0.0001 [−0.0019, +0.0022] and mean-fire average precision from +0.0039 to +0.0006, and neither excludes zero any more. What radar still does is move structures across the cut — recall 0.897 → 0.921 for a precision cost of 0.931 → 0.927 — and it still does it where it was supposed to, on bare ground. It no longer demonstrably improves the ranking. Re-applying the bar that promoted it in the first place, it clears two of five criteria; the owner's decision on 2026-09-11 was to drop it.

05 · the honest limit

Nothing here is a forward hold-out

Every damage interval on this page is cross-validated or leave-one-fire-out. The production bundle has seen all eight DINS incidents, so the leave-one-incident-out table is its only honest score — and the fix is time, not a better estimator.

On 2026-09-10 the production bundles were frozen and hashed — seven files, 295,298,842 bytes — along with the operating cut, the composite windows and the code commit. Nothing has been predicted, because there is nothing yet to predict on: a complete snapshot of the public CAL FIRE DINS archive taken the same day holds 132,522 records covering 2013–2025 and zero incidents of 2026; the latest ignition anywhere in it is 2025-11-23 and the layer's own dataLastEditDate is 2026-01-06. The same selection rule applied to 2025 picks exactly the five 2025 fires already in the forward set, so the empty result is the archive, not the query. This project uses public data only, so the hold-out waits on CAL FIRE.

When a qualifying incident appears it is scored with the frozen bundles at the frozen cut against these fixed reference numbers: detection n-weighted recall 0.786 all / 0.878 major over the 15 forward fires; damage leave-one-fire-out pooled F1 0.9122 and mean-fire F1 0.8690; and, end to end on Nixon 2024, P / R / F1 0.733 with AUC 0.965. A later score under a changed operating rule or a different bundle is reported as a separate labelled row, never as a replacement.
